# Vibe Coding 记录

## 2026-06-05：从 0 到首版方向

### 初始认知

用户当前对 vibe coding 的理解包括：

- Codex 可以辅助完成 vibe coding
- 第一个项目需要体现产品思维
- 对代码能力要求相对低

### 本次决策

选择“AI 健身计划小程序”作为首个项目，因为它满足三个条件：

1. 需求容易理解，适合作品集讲述。
2. 能自然嵌入 AI 产品能力：个性化计划、解释、反馈、动态调整。
3. MVP 可以很小，但依然有完整闭环：输入信息、生成计划、执行训练、打卡反馈。

### 产品经理能力映射

| 项目动作 | 对应 PM 能力 |
| --- | --- |
| 明确新手健身人群 | 用户分层 |
| 聚焦计划生成和打卡 | 需求优先级 |
| 暂不做社交、视频、饮食 | MVP 取舍 |
| 设置生成率、打卡率、留存 | 指标意识 |
| 保留 AI 升级路径 | AI 产品规划 |

### Vibe Coding 方法

本项目采用“先产品闭环，后技术复杂度”的节奏：

1. 先写清楚要解决谁的什么问题。
2. 再做能跑的最小原型。
3. 用静态规则模拟 AI 能力。
4. 逐步替换为真实模型、数据库和小程序框架。

### 本轮完成目标

- 建立项目定位
- 形成 PRD v0.1
- 搭建可演示 H5 原型
- 留出后续迁移到微信小程序或 React 的空间

## 2026-06-17：产品方向关键转向

### 新产品方向

用户明确希望做一个面向健身新手的微信小程序，帮助他们识别健身器械、了解器械如何使用，并能分享给他人。

### 被挑战的假设

最初设想包括摄像机扫描、AI 识别或二维码识别。但进一步讨论后发现：

- AI 视觉识别可能受角度、遮挡、品牌差异影响，误识别会带来训练安全风险。
- 二维码需要稳定贴在器械上，但公共健身房或非合作场景下很难长期维护。
- 摄像机扫描如果不上传画面，本地识别技术复杂度高，不适合第一个可分享版本。

### 新 MVP

将第一版改为：

> 器械图鉴 + 外观问答定位 + 新手使用教学

用户不需要拍照、不需要上传照片、不需要扫码。通过选择训练部位和外观特征，系统推荐可能器械，再由用户确认并查看教学。

### 产品经理能力映射

| 决策 | 体现的能力 |
| --- | --- |
| 放弃 AI 视觉识别作为 V1 主路径 | 风险识别和 MVP 取舍 |
| 放弃二维码主路径 | 线下场景约束判断 |
| 保留 AI 作为后续增强 | 技术路线分阶段规划 |
| 优先做图鉴和问答定位 | 以稳定解决用户问题为先 |
