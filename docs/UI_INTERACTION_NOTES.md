# 前端交互设计说明 v0.1

## 设计目标

练器助手的前端不追求花哨，而是解决健身新手在现场的三个问题：

1. 我该从哪里开始？
2. 我怎么判断眼前是哪台器械？
3. 我确认后能不能马上学会怎么安全使用？

因此界面采用“入口明确、步骤清晰、结果可确认”的设计。

## 页面策略

### 首页

首页承担第一次打开时的解释任务，但不做长篇介绍。用户可以立刻看到：

- 这是新手健身器械指南
- 不上传照片
- 当前覆盖多少台常见器械
- 主入口是“我看到一台器械”

新增的常见器械横向卡片，是为了让用户不必理解完整流程，也可以先点进一台器械试用。

### 找器械页

找器械页被设计成一个“渐进式缩小范围”的流程：

1. 先选训练部位
2. 再选外观特征
3. 系统给出候选结果

进度条不是技术识别进度，而是用户输入充分度提示。它告诉用户：信息越具体，结果越可靠。

### 图鉴页

图鉴页是兜底入口。用户知道器械名字时可以搜索，不知道名字时可以按训练部位浏览。

### 详情页

详情页被设计成“现场教练卡片”，信息顺序是：

1. 它是什么、练哪里
2. 先怎么调
3. 动作怎么做
4. 常见错误
5. 安全提醒
6. 新手组数

底部固定操作区让用户在看完后可以快速收藏，或回到找器械流程。

## 当前不做的交互

- 不做摄像头扫描，因为 V1 不依赖视觉识别。
- 不做复杂动画，避免影响现场使用效率。
- 不做社区和分享海报，先把核心学习链路打磨好。

## 下一步界面增强

1. 为每台器械补充真实图片。
2. 增加“没找到这台器械”反馈按钮。
3. 增加器械详情页的动作示意图。
4. 增加训练中计时和组间休息提示。
